# `@islee23520/lfg` v0.1.30 — BREAKING upgrade

Version 0.1.30 changes the installed Grok orchestration model. Before installing it, remove the previous lfg-owned plugin, hooks, generated agents, roles, prompts, overrides, and wrapper. A normal preserve-mode setup does not remove every artifact left by mixed older plugin generations.

## Why a complete wipe is required

The release establishes one coherent runtime contract:

- **Codex-only implementation:** Grok is the Sisyphus watcher/orchestrator. Product implementation and technical judgment run through external Codex, not an in-host Grok implementer.
- **LazyCodex handoff facade and automatic monitoring:** `lazycodex` is a read-only handoff facade that launches or attaches the Codex worker and monitors its RESULT artifact. It is not a second local implementer.
- **SessionStart automatic resume:** the orchestrator inbox can restore pending work into a new Grok session through the `lfg-session-auto-resume` context.
- **Forced goal routing:** goal intent is marked as `Intent: goal` and routed to the Codex `$start-work` path through `lfg --json plan start-work`.
- **Forced planning routing:** planning is routed to the Codex `$ulw-plan` path through `lfg --json plan ulw-plan`.
- **CEO no-edit boundary:** the Grok watcher coordinates, delegates, monitors, and synthesizes results, but does not edit the product workspace itself.

Older installations may contain agents, prompts, hooks, and wrappers from several incompatible topologies. Leaving even one stale copy can cause duplicate SessionStart instructions, an old in-host implementer route, conflicting agent permissions, or a preserve-mode install that appears healthy while Grok still loads obsolete global files.

## What to delete and what to keep

| Path or data | Ownership | Action |
|---|---|---|
| `~/.grok/plugins/lfg` | lfg-owned current plugin payload | Safe to delete; required for this upgrade |
| `~/.grok/installed-plugins/lfg` | lfg-owned legacy plugin payload | Safe to delete; required when present |
| `~/.grok/hooks/lfg-hooks.json` | lfg-owned global hook registration | Safe to delete; required |
| Named lfg agent, role, and prompt files listed below | Generated by lfg | Safe to delete; required for core names, optional for retired names |
| `~/.grok/prompts/lazycodex` | lfg/LazyCodex legacy prompt tree | Safe to delete; required when present |
| `~/.grok/omo-agent-overrides.json` | lfg-owned generated/user override surface | Back up, then delete for a clean topology |
| `~/.grok/lazycodex-agent-overrides.json` | lfg-owned legacy override surface | Back up, then delete |
| `~/.grok/bin/lfg` | lfg-owned Grok wrapper | Safe to delete; delete this file only |
| `~/.grok/auth.json` | Grok-owned authentication | **Keep** |
| `~/.grok/bin/grok` | Grok executable | **Keep** |
| `~/.grok/downloads` | Grok-owned downloads/cache | **Keep** |
| `~/.grok/config.toml` | Shared Grok and lfg configuration | **Keep the whole file. Back it up and inspect it carefully; do not delete it wholesale.** |

The required generated names are `sisyphus`, `watcher`, `lazycodex`, `explorer`, and `git-master`. If they remain from an older topology, also remove the retired optional names `hephaestus`, `prometheus`, `atlas`, and `oracle`. For each name, the generated paths are:

- `~/.grok/agents/<name>.toml`
- `~/.grok/roles/<name>.toml`
- `~/.grok/prompts/omo/<name>.md`

Project-local state is not part of the global wipe. If a project contains a stale pending orchestration receipt that must not resume, optionally back up and remove `.omo/orchestrator/inbox.json` in that project before opening the new Grok session.

## 1. Back up the previous installation

Run this from a directory where the backup folder may be created:

```sh
set -eu

stamp="$(date +%Y%m%d-%H%M%S)"
backup_dir="./lfg-v0.1.30-backup-$stamp"
mkdir -p "$backup_dir/.grok"

for path in \
  ~/.grok/plugins/lfg \
  ~/.grok/installed-plugins/lfg \
  ~/.grok/hooks/lfg-hooks.json \
  ~/.grok/prompts/lazycodex \
  ~/.grok/omo-agent-overrides.json \
  ~/.grok/lazycodex-agent-overrides.json \
  ~/.grok/bin/lfg \
  ~/.grok/config.toml
do
  if [ -e "$path" ]; then
    relative_path="${path#"$HOME"/}"
    mkdir -p "$backup_dir/$(dirname "$relative_path")"
    cp -Rp "$path" "$backup_dir/$relative_path"
  fi
done

for name in sisyphus watcher lazycodex explorer git-master hephaestus prometheus atlas oracle
do
  for path in \
    ~/.grok/agents/"$name".toml \
    ~/.grok/roles/"$name".toml \
    ~/.grok/prompts/omo/"$name".md
  do
    if [ -e "$path" ]; then
      relative_path="${path#"$HOME"/}"
      mkdir -p "$backup_dir/$(dirname "$relative_path")"
      cp -Rp "$path" "$backup_dir/$relative_path"
    fi
  done
done

printf 'Backup created at %s\n' "$backup_dir"
```

This backup intentionally includes `~/.grok/config.toml` for rollback, but the wipe below does not delete it.

## 2. Remove only the previous lfg-owned surface

Review the commands, then copy and paste them:

```sh
set -eu

rm -rf \
  ~/.grok/plugins/lfg \
  ~/.grok/installed-plugins/lfg \
  ~/.grok/prompts/lazycodex

rm -f \
  ~/.grok/hooks/lfg-hooks.json \
  ~/.grok/omo-agent-overrides.json \
  ~/.grok/lazycodex-agent-overrides.json \
  ~/.grok/bin/lfg

for name in sisyphus watcher lazycodex explorer git-master hephaestus prometheus atlas oracle
do
  rm -f \
    ~/.grok/agents/"$name".toml \
    ~/.grok/roles/"$name".toml \
    ~/.grok/prompts/omo/"$name".md
done
```

Do not remove `~/.grok/auth.json`, `~/.grok/bin/grok`, `~/.grok/downloads`, or the whole `~/.grok/config.toml`.

If a project should not resume its previous pending assignment, optionally run this from that project after backing up the file:

```sh
rm -f .omo/orchestrator/inbox.json
```

## 3. Install v0.1.30 with force

```sh
npx @islee23520/lfg@0.1.30 --json setup --run --force
```

The wipe and `--force` are both intentional. Running `setup --run` without `--force` is **not enough** after mixed old plugins: preserve mode can retain a stamped tree and cannot guarantee removal of stale global agents, prompts, overrides, or hook registrations from earlier layouts.

## 4. Verify the installed contract

First inspect the JSON result from the install command. It must report a successful setup and verification result without exposing or requiring changes to Grok authentication.

Then run these checks:

```sh
grep -R -n "lfg-session-auto-resume" ~/.grok/hooks ~/.grok/plugins/lfg
grep -R -n "Intent: goal" ~/.grok/hooks ~/.grok/plugins/lfg
grep -R -n "plan start-work" ~/.grok/hooks ~/.grok/plugins/lfg
grep -R -n "plan ulw-plan" ~/.grok/hooks ~/.grok/plugins/lfg
grep -n "LazyCodex handoff facade" ~/.grok/plugins/lfg/agents/lazycodex.md
```

Every command must print at least one matching line. The last command confirms that `lazycodex.md` describes the handoff facade rather than an in-host implementer.

## 5. Start a new Grok session

A new Grok session is required after installation. Existing sessions may retain the old system prompt, agent definitions, hook context, or orchestration state in memory even when the files on disk are correct.

## Rollback

If the upgrade must be rolled back:

1. Close the Grok session.
2. Remove the newly generated lfg-owned paths listed in the wipe section.
3. Copy the saved `.grok` contents from `./lfg-v0.1.30-backup-<timestamp>` back to their matching `~/.grok` locations.
4. Restore the backed-up `~/.grok/config.toml` only if the upgrade changed configuration that must also be reverted.
5. Start a new Grok session and verify the restored version before resuming work.

For step 3, replace the placeholder with the actual backup directory:

```sh
backup_dir="./lfg-v0.1.30-backup-YYYYMMDD-HHMMSS"
cp -Rp "$backup_dir/.grok/." ~/.grok/
```

Keep the backup until the new topology has been verified in a fresh session.
